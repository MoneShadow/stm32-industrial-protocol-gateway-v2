# 网关协议说明

> 本文以 `gateway-f407` 当前代码为准。  
> 角色：PC 是 Modbus TCP 主站，F407 是网关，F103 是 CAN 下位机。

---

## 1. Modbus TCP

### 1.1 连接参数

| 项目 | 当前值 |
|---|---|
| 默认 IP | `192.168.0.200` |
| 子网掩码 | `255.255.255.0` |
| 端口 | `502` |
| 最大 TCP 客户端 | 4 |
| Unit ID | 当前不校验，原样回显；建议填 `1` |
| 字节序 | Modbus 侧为大端 |

响应会带回请求里的 Transaction ID 和 Unit ID。

### 1.2 支持的功能码

当前只支持：

| 功能码 | 含义 | 说明 |
|---|---|---|
| `0x03` | 读保持寄存器 | 一次最多读 7 个 |
| `0x06` | 写单个保持寄存器 | 只支持写 `0x0002`、`0x0003` |

不支持的功能码返回异常 `0x01`。

### 1.3 寄存器表

| 地址 | 读写 | 名称 | 含义 |
|---|---|---|---|
| `0x0000` | R | `temperature` | 温度，按 `×0.1℃` 解释 |
| `0x0001` | R | `light` | 光照值，原始值 |
| `0x0002` | R/W | `fan_rpm` | 读：下位机上报的实际转速；写：目标转速 `0~3000` |
| `0x0003` | R/W | `led_state` | 读：下位机上报的 LED 状态；写：`0` 关、`1` 开 |
| `0x0004` | R | `cmd_result` | 写命令结果：`0` 成功、`1` 在途、`2` 失败、`3` 超时 |
| `0x0005` | R | `online` | `0` 在线、`1` 离线 |
| `0x0006` | R | `protocol_version` | 当前固定为 `1` |

有效寄存器范围是 `0x0000~0x0006`，单次读取数量不能超过 7。

`cmd_result` 和 `online` 是只读状态，不是写命令寄存器。

---

## 2. 读写语义

### 2.1 读寄存器

读请求**不会发到 CAN 总线**。

网关自己维护一份设备状态缓存：

```text
下位机 --CAN 0x101--> F407 更新缓存
PC --Modbus 0x03--> F407 直接读缓存
```

所以：

- 温度、光照、风扇、LED 的读值来自下位机主动上报的 `0x101`；
- 没有收到过状态帧时，读出来是初始值 `0`；
- `online` 初始为 `1`（离线），收到心跳后变 `0`；
- 读 `cmd_result` 可以在写命令在途时观察 `1`。

### 2.2 写风扇/LED

只支持写：

```text
0x0002 = 目标风扇转速（0~3000）
0x0003 = LED 状态（0 或 1）
```

写入后：

1. 网关立即返回 Modbus 写回显；
2. 网关把命令转成 CAN `0x301`；
3. 下位机执行后回 CAN `0x401`；
4. 网关根据 ACK 更新 `cmd_result`。

**写回显只表示网关接受了请求，不表示下位机已经执行。**

写入不会直接修改 `0x0002/0x0003` 的读缓存；读值仍然来自下位机后续上报的 `0x101` 状态帧。

同一时间只允许一条写命令在途。前一条还没结束时，新的写请求返回异常 `0x06`（设备忙）。读请求不受这个限制，仍然可以读 `cmd_result`、温度和在线状态。

### 2.3 `cmd_result` 的完整含义

| 值 | 含义 | 产生条件 |
|---:|---|---|
| 0 | 成功 | 收到匹配的 `0x401`，且 ACK 结果为 0 |
| 1 | 在途 | CAN `0x301` 已发出，正在等 ACK |
| 2 | 失败 | 收到 ACK 但结果非 0，或 CAN 发送失败 |
| 3 | 超时 | 1 秒内没有收到匹配的 ACK |

典型的写命令时序：

```text
PC 写 0x0003 = 1
  -> F407 回写回显
  -> cmd_result = 1
  -> CAN 0x301 发出
  -> 收到 0x401 成功：cmd_result = 0
  -> 收到 0x401 失败：cmd_result = 2
  -> 1 秒内没有 ACK：cmd_result = 3
```

### 2.4 异常响应

当前实现使用的异常码：

| 异常码 | 含义 | 当前触发场景 |
|---|---|---|
| `0x01` | 非法功能码 | 不是 `0x03`/`0x06` |
| `0x02` | 非法地址 | PDU 长度/地址解析失败 |
| `0x03` | 非法数据值 | PDU 解析阶段的数量/参数值非法 |
| `0x04` | 服务器设备故障 | 内部解码/设备模型异常 |
| `0x06` | 服务器设备忙 | 有命令在途、队列忙、写地址或写值校验失败 |

说明：

- 当前写只读寄存器、写不支持的地址、风扇/LED 值非法，都会统一返回 `0x06`；
- 这不是最细的标准映射，后续可以把地址错误拆成 `0x02`、值错误拆成 `0x03`；
- 当前不再使用 `0x05`。`0x05` 在 Modbus 里表示 Acknowledge，不是“输入失败”。

## 3. CAN 协议

### 3.1 基本参数

| 项目 | 当前值 |
|---|---|
| 波特率 | 500 kbps |
| 帧类型 | 标准数据帧，11 位 ID |
| 多字节字节序 | 小端 |

网关只处理下面 4 个总线报文，另有 1 个内部伪帧。

### 3.2 报文总表

| ID | 方向 | DLC | 作用 |
|---|---|---|---|
| `0x101` | F103 → F407 | 8 | 温度/光照/风扇/LED 状态 |
| `0x201` | F103 → F407 | 2 | 心跳 |
| `0x301` | F407 → F103 | 8 | 风扇/LED 命令 |
| `0x401` | F103 → F407 | 3 | 命令 ACK |
| `0x501` | 仅 F407 内部 | 1~7 | 读寄存器伪帧，不上 CAN 总线 |

### 3.3 `0x101` 状态帧

DLC = 8。

```text
Byte 0-1  温度 ×10，小端
Byte 2-3  光照，小端
Byte 4-5  风扇转速，小端
Byte 6    LED 状态
Byte 7    保留
```

### 3.4 `0x201` 心跳帧

DLC = 2。

```text
Byte 0  Node ID，当前为 1
Byte 1  心跳序号
```

网关超过 **1500ms** 没收到心跳，就把 `online` 置为 `1`（离线）。

### 3.5 `0x301` 命令帧

DLC = 8。

```text
Byte 0    命令码：1 = 风扇转速，2 = LED
Byte 1    风扇转速低字节 / LED 状态
Byte 2    风扇转速高字节 / LED 命令填 0
Byte 3    命令序号
Byte 4-7  保留，填 0
```

风扇：

```text
Byte 0 = 1
Byte 1-2 = 目标转速，小端，范围 0~3000
Byte 3 = seq
```

LED：

```text
Byte 0 = 2
Byte 1 = 0 或 1
Byte 2 = 0
Byte 3 = seq
```

### 3.6 `0x401` ACK 帧

DLC = 3。

```text
Byte 0  原命令码
Byte 1  结果：0 成功、1 失败、2 非法
Byte 2  原命令序号
```

网关只在“命令码 + 序号”都匹配当前在途命令时，才更新 `cmd_result`。

### 3.7 `0x501` 内部伪帧

读寄存器时，网关内部会生成一个 `0x501` 的伪帧，用来表示“要读哪几个寄存器”。

它只存在于 F407 的任务队列里，**不会真的发到 CAN 总线**。读值来自网关缓存，不来自下位机实时回读。

## 4. 当前对端状态

F103 侧目前保留的是 CAN 底层收发和测试代码；`0x101`、`0x201`、`0x401` 的自动发送还需要下位机业务代码实现。

因此当前联调时可能出现：

- PC 读寄存器正常，因为读的是 F407 缓存；
- PC 写风扇/LED 后，`cmd_result` 最终变成 `3`，因为下位机还没有自动回 ACK；
- 这不是 Modbus TCP 不通，而是 CAN 命令没有收到确认。

F103 业务代码补齐后，写命令才能形成完整的“写命令 → CAN 0x301 → ACK 0x401 → cmd_result”闭环。

---

## 5. 时序汇总

| 项目 | 时间 |
|---|---:|
| 下位机状态帧 `0x101` | 约定 500ms 一帧 |
| 下位机心跳 `0x201` | 约定 500ms 一帧 |
| 网关判定离线 | 1500ms 无心跳 |
| 网关等待 ACK | 1000ms |

---

## 6. 当前实现边界

- 只支持 Modbus TCP，不支持 RTU/ASCII；
- 只支持 `0x03` 读和 `0x06` 写；
- 一次最多读 7 个寄存器；
- 只支持写 `0x0002`、`0x0003`；
- 同一时间只允许一条写命令在途；
- Unit ID 不校验，建议固定用 `1`；
- 写只读寄存器/非法地址目前统一回 `0x06`，后续可以拆细；
- 网络 link 的周期检查还没做，建议上电前插好网线；
- 没有掉电保存，重启后寄存器恢复默认值；
- 没有用户认证、权限和加密，适合实验室/课程环境，不适合直接上生产现场。
